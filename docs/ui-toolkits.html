Which UI toolkit should viewSEG use?

A survey of the Nim GUI ecosystem against what a SEG-Y / SEG-D viewer needs, on Windows and Linux.

−A0+A

Decided 13 Nov 2026: imguin + ImPlot on SDL3 / OpenGL 3, no prototypes. The GUI layer stays swappable.

Conclusion

  1. Build on Dear ImGui through imguin, with ImPlot.recommended
    It is the only Nim option that already covers the hard generic parts: panels you can drag onto another monitor, interactive plots with crosshair and cursor readout, virtualized tables, and trees. It renders on the GPU by default.
  2. Qt 6 Widgets through seaqt is the fallback.runner-up
    Choose it if a native-looking, accessible desktop application matters more than plotting speed. It costs a preview-stage binding, a harder Windows build, and plots you draw yourself.
  3. Watch Merenda and retroui.watch
    These are the new pure-Nim toolkits from 2026. Merenda is the best long-term place to contribute widgets, but neither is mature enough to build on today.
  4. The seismic-specific parts are custom work in every toolkit.
    That means the trace panel, the hover readout on traces and the survey map. So the choice comes down to the application shell, the drawing surface, and project health. Before committing, prove the choice with two short prototypes (one per finalist).

What the viewer needs

From your brief, plus R6, which a seismic viewer implies even though you did not list it.

  • R1Open files (file dialogs)
  • R2Lists and trees (navigation)
  • R3Tables, large and editable (headers)
  • R4Graphs and charts
  • R5Interactive plots with cursor readout
  • R6Large colour-mapped raster (a 3000 × 2000 trace panel)
  • R7Map with selectable points and lines
  • R8Movable windows; panels on other monitors
  • R9Windows and Linux

The deciding factor. No toolkit ships a seismic trace panel (variable density or wiggle), a trace-aware hover readout, or a survey map with shot and receiver selection. You will write those, so they are where your widget contributions will go. Judge the toolkit on what it saves you everywhere else: docking, tables, plots and multi-monitor windows. Judge it also on how good a surface it gives you to draw on.

The shortlist

imguin: Dear ImGui (docking) + ImPlot recommended

github.com/dinau/imguin · MIT · ImGui 1.92.x docking · last push Sep 2026 · Futhark-generated, cimgui C API

ImGui is the de facto toolkit for engineering and scientific tools. imguin tracks each upstream release within about a month and bundles ImPlot, ImPlot3D, ImGuiFileDialog, ImNodes and a zoomable-image widget. You build it with plain nim c. Backends are GLFW or SDL2/SDL3 with OpenGL 3 or Vulkan.

Pros

  • Docking plus multi-viewport: drag a panel out of the window onto another monitor (R8).
  • ImPlot: crosshairs, plot-space mouse position, drag lines and rectangles, linked axes, heatmaps and images (R4, R5).
  • Tables with a clipper handle hundreds of thousands of header rows (R3).
  • GPU by default. A float32 texture plus a shader colour map makes pan, zoom, gain and colour-map changes nearly free (R6).
  • A tile-map recipe exists (implot_demos maps.cpp) to port and publish as a Nim package (R7).
  • The binding is thin and generated, so we could regenerate it ourselves if dinau stops.

Cons

  • Looks like a tool, not a native application. No screen-reader support, and IME is basic.
  • Needs a C++ compiler for the ImGui sources. On Windows the documented route is MSYS2.
  • Multi-viewport is weak on native Wayland. On Hyprland, run GLFW on X11 (Xwayland).
  • Immediate mode redraws every frame. Throttle when idle.
  • Nim 2.4 is not stated as tested (it needs ≥ 2.2.4).
  • The file dialog is drawn by ImGui. Add a native-dialog binding later if wanted.

seaqt: Qt 6 Widgets runner-up

github.com/seaqt/nim-seaqt · bindings MIT, Qt LGPLv3 · Qt 5.15–6.11 branches · regenerated Jul 2026

Generated bindings for Core, Gui, Widgets, Qml/Quick, Network, Svg, Pdf, WebEngine and Positioning. Item models can be subclassed from Nim. It is the most complete native application shell available to Nim.

Pros

  • Native file dialogs, tree and table views on real models, floating dock widgets, accessibility, and a polished look.
  • A map view is reachable without new bindings: a QML MapView embedded in a widget.
  • Strong vendor ecosystem, and the bindings are backed by Status/Logos work.

Cons

  • Preview: “may occasionally be rebased”, no tagged release, custom signals and slots still in progress.
  • QtCharts and QtGraphs are not bound and are GPL/commercial, so plots mean hand-written QPainter code.
  • QOpenGLWidget is not bound. The raster path is CPU QImage, or QRhiWidget on 6.11.
  • Windows build described by a user as “a short but intense war”. You also need a C++ toolchain.
  • You must hand ownership to Qt manually (owner = false), or you get double frees.
  • LGPL means shipping Qt as DLLs, roughly 50 MB or more.

Merenda (NimKit) watch

github.com/elcritch/merenda · BSD-3 · v0.31.2 (9 Nov 2026) · Nim ≥ 2.2.10, ORC + threads, Atlas

A pure-Nim toolkit in the style of Apple's Cocoa (Mac) framework, drawn on the GPU with FigDraw, with text shaping. It has table, outline, split, tab and dock views, multiple windows, CSS-style theming and an interface builder. A full code editor, Kosmo, is built on it. It is probably part of the “new stuff” you saw.

Pros

  • Retained-mode model–view design, which is the best structure for upstreaming viewer widgets to the Nim ecosystem.
  • Pure Nim end to end, with no C++ and no foreign runtime.
  • Very active, and the maintainer engages on the forum.

Cons

  • One developer, pre-1.0, with parts described as “vibe coded”.
  • No plots, no map, and docks cannot leave their window.
  • X11 only on Linux, and there have been X11 bugs.
  • Large-table performance, IME and accessibility are unverified.

retroui watch

github.com/foxoman/retroui · MIT · created 6 Nov 2026 · v0.46.0 · built on a fork of Araq's uirelays

On paper this covers the most of your list: an editable virtual grid, a tree grid, a tile map with PMTiles and click-to-coordinate, 21 chart types, screen readers and IME. It has been public for one week and was written with AI help, so read its source for ideas but don't build on it yet.

Web hybrid: webui or Neel, with JavaScript libraries

nim-webui (MIT, C core Oct 2026) · Neel 2.1 (MIT, Oct 2026) · AG Grid, uPlot, ECharts, MapLibre, deck.gl

This has the best ready-made widgets, especially for maps. It is the wrong shape for a high-performance viewer: every trace panel crosses a local socket as a copy (about 24 MB for 3000 × 2000 float32). It also means a second language, and WebGL on Linux WebKitGTK is uneven. Neel avoids WebKitGTK only by requiring an installed Chrome or Edge. Keep it in mind for a lightweight companion app, such as a survey map in a browser.

Do you need GPU acceleration?

Not to start, but it is the right default. A 3000 × 2000 panel is 6 M samples. Colour-mapping it on the CPU per frame takes milliseconds to tens of milliseconds, depending on SIMD and threads. That is fine if you redraw only on change, but it becomes noticeable when gain, clip or colour map follow a slider, or when panning at 4K.

With the samples in a float32 texture and the colour map in a shader, those changes cost almost nothing. The CPU then only handles reading, processing and tiling. ImGui, Merenda and Silky are GPU-based anyway. Qt's widget path is CPU unless you use QRhiWidget.

Multi-monitor on your machine

Dragging an ImGui panel to another monitor needs the app to place top-level windows itself. Native Wayland does not allow that; X11 and Windows do. On Hyprland, run with GLFW (or SDL) on the X11 backend under Xwayland. The viewSEG devcontainer already passes DISPLAY=:0 for this. Qt's floating docks have the same Wayland limitation.

Next steps

  1. Prototype A, imguin, about two days:
    • Docking, with a panel dragged to a second monitor on Windows and on Hyprland (Xwayland).
    • A 3000 × 2000 float32 panel as an R32F texture with a shader colour map inside ImPlot: pan, zoom, crosshair readout of the sample value, and the frame time.
    • A 100k-row trace-header table with inline editing.
    • Open a real SEG-Y through parseSEG.
    • A minimal tile map with selectable points.
  2. Prototype B, seaqt: the same first four items, using a floating QDockWidget for the monitor test. Optionally, a half-day Merenda check of the table and image views.
  3. Decide from the frame times, the build friction on Windows, and how the code reads. Record the choice in docs/architecture.md.
  4. Keep the seams. Put viewer state, colour-map kernels, tile cache and selection in plain Nim modules with no UI imports, so a later move (for example to Merenda once it matures) only replaces the UI layer.
  5. Contribute. The trace panel, the tile-map widget and a native file dialog binding are the natural pieces to publish for the chosen toolkit.

Confidence

On 13 Nov 2026, four parallel research passes read each project's GitHub repository (commit dates, file trees, READMEs) and the Nim forum. Nothing was built or run. These points are unverified and are exactly what the prototypes test:

  • imguin on Nim 2.4.
  • Multi-viewport behaviour at runtime.
  • Merenda's large-table performance.
  • retroui's own feature claims.
  • Whether webui's Nim wrapper exposes its binary calls.
